!TOPIC 302 NetWare
Novell supplies only C language routines to access the power of their
Advanced NetWare operating system. The NetWare unit supplied here
implements many of the NetWare application program interfaces (APIs). The
tools in the NetWare unit access such facilities as the network print
spooler, messaging services, direct station-to-station communications,
NetWare SFT's Transaction Tracking Services, and others.

The routines within this unit are specific to Novell's NetWare
environment. Some operating systems claiming to be NetWare compatible may
support some of these functions, but it is unlikely that they will support
all.

As of version 5.23, NetWare may be used with Turbo Pascal for Windows, under
Windows 3.0 or later running in Standard or Enhanced mode. There are minor
differences in the calling sequences of some NetWare routines when used
under Windows. Such headers are listed separately after the DOS calling
sequence for the affected routines. There are also a few new Windows-specific
types and procedures, which appear under the Windows declarations topic below.

The following categories of services are available:

  0338Advanced messaging             0337Basic messaging
  0304Declarations                   0303File and directory
  0346Miscellaneous                  0336Printer services

!TOPIC 339 IPX
!NOINDEX
!NOSEARCH
IPX stands for Internetwork Packet eXchange protocol. It is Novell's
implementation of the Internetwork Datagram Packet Protocol designed by
Xerox. Applications running under versions of NetWare that support
IPX can communicate directly with other workstations, servers or devices.

The NetWare unit implements IPX routines ranging from low to high
levels of integration. The low level routines are simple Pascal procedures
and functions that call the NetWare IPX services directly. The higher
level routines isolate the programmer from the details of forming IPX
packets. Application developers should use the high level routines. The low
level routines all end with the word Prim (as in IPXSendPrim).

The following routines relate to IPX services:

  0420IPXAssignUniqueSocket          0422IPXCancelEvent
  0419IPXCloseSocket                 0421IPXEventComplete
  0416IPXGetIntervalMarker           0417IPXGetLocalTarget
  0413IPXInternetAddress             0424IPXListen
  0418IPXOpenSocket                  0412IPXRelinquish
  0414IPXScheduleEvent               0415IPXScheduleSpecialEvent
  0423IPXSend                        0406IPXServicesAvail

!TOPIC 342 SPX
!NOINDEX
!NOSEARCH
Advanced NetWare 2 implements a high level node-to-node communication
facility called SPX (Sequenced Packet eXchange Protocol). SPX is
based on the Sequenced Packet Protocol defined by Xerox. IPX
implements NetWare datagram services, and SPX implements the higher
level session services.

Building upon IPX services, SPX provides a guaranteed delivery system
for packets of data. SPX automatically selects appropriate timeout and
retransmission counts based on the physical characteristics of the network
hardware. Hence, applications using SPX need not be concerned with the
details of the guaranteed delivery system.

A receiver of SPX messages must make more than one event control block
available to handle incoming messages. The SPX routines in the NetWare
unit make this easy by automatically managing a pool of event control
blocks. When an application establishes an SPX connection, it simply
specifies the number of event control blocks and the maximum size of each
data packet. The demonstration program NRECEIVE is a good example of the
use of these pools and their associated procedures and functions.

The following routines relate to SPX services:

  0438SPXAbortConn                   0430SPXConnStatus
  0434SPXEstablishConn               0433SPXEventComplete
  0446SPXListenCount                 0435SPXListenForConn
  0440SPXListenPooled                0439SPXPoolCancelAll
  0442SPXPoolDataPtr                 0441SPXPoolECBPtr
  0443SPXPoolStartListening          0445SPXReplenishAll
  0444SPXReplenishPool               0436SPXSend

!TOPIC 407 IPXSendPrim
!NOINDEX
procedure 0302NetWare.IPXSendPrim(var ECB);

This procedure prepares an ECB and the IPX header of its associated
packet and passes the ECB to the network drivers to initiate a send
operation. This function returns immediately to the calling application. In
other words, the send event cannot be assumed completed when this function
returns. When the send event has been completed by the driver, the InUse
flag of the ECB is reset to 0 (it is $FF while the send event is
pending). If the ESRAddress pointer within the IPXECB is not Nil, then
the Event Service Routine (the code pointed to by the ESRAddress field)
will be called upon completion of the send request (see documentation
regarding the limitations of ESRs).

!NOWRAP
Valid CompletionCode values are:
  $00  = The send completed successfully.
  $FC  = The send request was cancelled by an IPXCloseSocket or an
         IPXCancelEvent function call (IPXEventCancelled).
  $FD  = Malformed Packet - either the packet was less than 30 bytes,
         the first fragment was too small for the header, or the
         fragment count was zero (IPXMalformedPacket).
  $FE  = Packet is undeliverable (IPXPacketUndeliverable).
  $FF  = Physically unable to deliver packet, possibly due to hardware
         or network failure (IPXPhysicalError).
!WRAP

This routine may not be called under Windows.

See also:  0408IPXListenPrim
;
;-------------------------------------------------------------------
!TOPIC 408 IPXListenPrim
!NOINDEX
procedure 0302NetWare.IPXListenPrim(var ECB);

This procedure delivers the specified ECB to the IPX driver for the purpose
of receiving an IPX packet. It returns immediately to the calling
application. This procedure only delivers the ECB to the driver; it does
not wait for delivery of the packet. While the driver is awaiting receipt
of a packet after a call to IPXListenPrim, the InUse field of the
passed ECB is set to $FE. This field remains set until a receive event
occurs, the request is cancelled, or IPX deems the ECB to be unusable.

After the InUse flag is reset to zero, the CompletionCode field of the
ECB contains one of the following values:

  $00  = The Packet was received successfully.
  $FC  = The receive request was cancelled by an IPXCloseSocket or an
         0422IPXCancelEvent function call (IPXEventCancelled).
  $FD  = Packet Overflow.  A packet was received, but the ECB's fragment
         count was zero, or the space defined by the ECB's fragment
         descriptor list was not large enough to contain the entire
         packet (IPXPacketOverflow)
  $FF  = Socket specified to listen on in ECB was not open
         (IPXSocketNotOpen)

The received packet is placed into memory based on the ECB's fragment
descriptor list. See the documentation regarding Fragment Descriptor Lists.

This routine may not be called under Windows.

See also:  0407IPXSendPrim
;

!TOPIC 412 IPXRelinquish

procedure 0302NetWare.IPXRelinquish;

This procedure serves one of two purposes, depending on whether it is
invoked from a file server/bridge, or a workstation. On a file server or
